# Permanent release protocol

All distribution follows [the permanent owner policy](GITHUB_DISTRIBUTION_POLICY.md). The sole public distribution location is the repository's native GitHub Releases section. Never add asset URLs, download buttons, mirrors, proxies or alternate distribution files.

A cohesive application milestone increments the workspace version, updates the lockfile, badge, changelog, handoff and release notes, and receives an immutable matching annotated tag on main. Never reuse or move a published tag. Preserve all historical releases and measurements.

The dedicated release workflow requires an exact tag/version/source commit match, the exact final README and release-note memorial, correctly cased local artwork and documentation, formatting, strict workspace Clippy, workspace regression tests, Windows and Linux release builds, cargo-deny policy checks, and exact CLI version smoke tests. Packages contain the actual native graphical executable, CLI, MIT license and complete offline README assets and documentation. GUI launch behavior still depends on the target computer's display and graphics drivers; the CI CLI smoke test is not a graphical rendering benchmark.

Publication requires the standalone Windows executable, Windows portable package, Linux package, source archive, RELEASE_MANIFEST.json and SHA256SUMS.txt. The manifest records exact filenames, byte lengths, hashes, tag, source commit and signing mode. SHA-256 covers all four payloads and the manifest, plus the signature bundle when configured. The native Rust contract rejects missing assets, changed provenance, tampering and incomplete checksum coverage. Manifest and checksum creation refuse existing files.

Signing is optional and disabled unless the repository variable QML_SIGN_RELEASES equals true. The separate signing job receives only read permission and GitHub OIDC permission, and signs the manifest through Sigstore. Signed manual dispatches must run from the exact release tag, ensuring that the workflow identity is the tagged release workflow. Publication and independent verification check that exact workflow/tag certificate identity and the GitHub Actions OIDC issuer. Unsigned releases explicitly say not-configured; checksums alone do not authenticate their producer.

All jobs default to contents read. Only publication receives contents write; only signing receives id-token write. Publication refuses a pre-existing release, creates a new draft with complete assets and notes, and makes it public only after upload. It does not overwrite historical assets or use clobber. A failed draft remains for investigation and is not automatically replaced. Ordinary releases use draft false, prerelease false and latest true; prereleases require explicit owner authorization.

An independent job retrieves the native public release metadata and assets without authentication into ephemeral verification storage. It verifies exact asset coverage, public/latest/maturity flags, source commit, manifest, byte lengths and complete checksums, and the configured signature. This internal CI integrity check is not a user-facing downloader or an alternative distribution mechanism. No asset URLs are printed in reports or added to documentation.

Only a successful independent verification completes publication. Record source commit, Actions run, verification results, actual tests and remaining limitations in HANDOFF.md. Preserve MIT, every historical experiment and the exact memorial. A release is a reproducible engineering checkpoint, not evidence of scientific superiority or production maturity.

The read-only Verify native public release workflow can verify an existing immutable tag and full source commit without changing that release. This provides recovery verification when publication succeeded but a downstream job was skipped or interrupted. Optional signing must not suppress ordinary independent verification: the automatic verification job explicitly evaluates successful publication even when signing is skipped. A recovery run is recorded separately and does not overwrite or regenerate historical assets.
